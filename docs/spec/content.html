1 · Назначение

Документ закрывается вместе с задачей

Фиксирует целевое устройство бэкенда демо после переезда на ragu.api. Сверочный: каждый пункт приёмки закрывается отдельно.

Для чего

норма

Сверяться при реализации. Расхождение кода с этим документом — либо баг реализации, либо повод править документ осознанно.

Когда закрыт

критерий

Все 14 пунктов главы 13 отмечены. Это и означает готовность MVP к тестированию командой.

Чего здесь нет

граница

Устройство самого ragu.api — у него своя документация. Здесь только то, как демо его использует.

Главное архитектурное решение Бэкенд демо перестаёт знать про граф и про LLM. Он становится BFF: презентация, язык ответа, трейс для фронта и контракт с $mol. Всё остальное делает ragu.api.

4 · Топология

Два сервиса вместо одного

Граф, поиск и генерация уезжают в отдельный контейнер. Демо остаётся тонким.

Целевая топология

ragu-web-api

наш
HTTP фронта → презентация и трейс → RaguClient

владеетКонтрактом с $mol, координатами канваса, карточками галереи, языком ответа, сборкой трейса.

не владеетГрафом, поиском, LLM, бюджетами, возможностями корпуса.

ragu-api

внешний
HTTP → registry графов → движки RAGU

владеетЧтением графа, режимами поиска, генерацией, учётом токенов, бюджетами, admission control, реранкером.

не владеетНичем, что относится к внешнему виду демо.

Решение по развёртыванию Отдельный контейнер, не in-process. Причина: аутентификация, бюджеты, таймауты, admission control и собственные метрики приходят даром и не требуют повторной реализации. Память графов при этом не удваивается — она просто живёт в другом процессе.

6.1 · Чат

Вопрос уходит целиком в сервис

Ответ агента

Генерация делегирована. Наш бэкенд не обращается к LLM вообще.

sequenceDiagram
  participant F as Фронт
  participant W as ragu-web-api
  participant N as language.py
  participant R as ragu-api
  participant T as trace.py

  F->>W: POST /agent/messages
  W->>N: язык по последнему сообщению
  N-->>W: ru или en
  W->>R: search(mode, query, language, use_query_plan, rerank, params)
  Note over R: ретрив, реранк, генерация, учёт токенов
  R-->>W: answer, sources.meta, engines, usage
  W->>T: собрать AnswerTrace
  T-->>W: сущности, связи, чанки, тайминги, стоимость, энергия
  W-->>F: AgentResponse
Почему язык считаем сами, а промпт не переопределяем Проверка на живой LLM: пять разных русских вопросов, английский контекст, language=russian, температура 1.0 — пять русских ответов. Промпт RAGU язык держит. Прежнее сползание вызывалось тем, что в движок передавался язык индекса, а не вопроса.

9 · Ошибки

Каждый отказ виден и назван

Правило единое: сбой подсистемы не роняет запрос, но обязан быть в логе и в трейсе. Обратное стоило недели диагностики.

Маппинг ошибок сервиса

Клиент ветвится по code, а не по тексту сообщения.

flowchart TD
  A["RaguApiError"] --> B{"code"}
  B -->|"CAPABILITY_UNAVAILABLE · способность названа"| C["409 · режим гасится до конца сессии"]
  B -->|"CAPABILITY_UNAVAILABLE · null"| D["200 · пустой трейс, переформулировать"]
  B -->|"GRAPH_BUSY"| E["409 · корпус пересобирается"]
  B -->|"SERVICE_NOT_READY"| F["503 + Retry-After"]
  B -->|"TOO_MANY_REQUESTS"| G["429 · повторить с паузой"]
  B -->|"BUDGET_EXCEEDED"| H["429 · НЕ повторять"]
  B -->|"REQUEST_TIMEOUT"| I["504"]
  B -->|"INTERNAL_ERROR"| J["500 + request_id пользователю"]

Два разных 409

не путать

С названной способностью — режим на этом корпусе не заработает никогда. С null — хранилище есть, но запрос ничего не извлёк.

по missing_capability

Два разных 429

ретраи

TOO_MANY_REQUESTS повторять с паузой. BUDGET_EXCEEDED повторять бессмысленно — лимит запроса исчерпан.

слепой ретрай на 429 — ошибка

Сквозной id

есть

Наш request_id уходит в ragu-api заголовком. Одна строка ищется в логах обоих сервисов.

X-Request-ID
Деградация обязана быть видна Поля engines.degraded, engines.children и engines.rerank_error переносятся в трейс и показываются в UI. Тихая потеря качества, выглядящая как нормальный ответ, — та самая ошибка, которую мы уже совершили один раз.

15 · Выводы

Что этот переезд меняет по сути

1

Бэкенд демо перестаёт быть вторым движком RAGU

Сегодня он параллельно читает граф, строит движки и определяет возможности корпуса. После переезда он про граф не знает.

2

Деградация становится наблюдаемой по контракту

engines.degraded и rerank_error приходят полем, а не выводятся из косвенных признаков. Тихая потеря качества, стоившая недели, структурно исключается.

3

Язык ответа остаётся нашим продуктовым решением

Определяем по сообщению пользователя и передаём параметром. Промпт и генерация — сервиса, правило — наше.

4

Один пункт API решает, будет ли бэкенд без состояния

POST /relations/select — граница между «прокси» и «материализованная копия графа». Остальные девять пунктов уже закрыты.

5

Закрытие чек-листа и есть готовность MVP

Четырнадцать пунктов покрывают переезд, четыре новые фичи и два критерия качества. После них — тестирование командой.

Оговорки

Объёмы целевых модулей (≈120, ≈90 и далее) — оценка модели Claude Opus 5, а не замер: этих файлов ещё не существует. Замеренными являются только текущие цифры главы 3, снятые подсчётом строк по файлам.

Оценка «123 запроса на ragu_bio» получена делением 61 200 связей на потолок страницы 500. Задержка сборки в секундах не замерялась — это расчёт, а не измерение.

Проверка удержания языка проведена на одной модели (yandexgpt-5-pro), одном шаблоне (local_search) и синтетическом контексте, пять прогонов. На другой модели или на длинном реальном контексте поведение может отличаться.

Вес риска (высокий, средний) — суждение модели Claude Opus 5, не вычисленная метрика.

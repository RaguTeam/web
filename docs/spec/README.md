# Целевая спецификация бэкенда

Сверочный документ: как бэкенд демо должен выглядеть после переезда на `ragu.api`.
Закрытие всех 14 пунктов чек-листа в главе 13 означает готовность MVP к тестированию.

## Что здесь лежит

| Файл | Что это |
|---|---|
| `content.html` | содержание документа: 16 разделов, 6 диаграмм Mermaid |
| `meta.json` | шапка, панель фактов, KPI |

Собранный HTML **в репозиторий не коммитится**: он весит 5.7 МБ, потому что в него
вшивается `mermaid.min.js`, и каждая пересборка добавляла бы в историю новый блоб
такого же размера. В git лежат источники — они диффаются построчно.

## Как обновить статус пункта

Правится `content.html`, таблица `#acctbl` в разделе «Приёмка». Статус — в последней
ячейке строки:

```html
<span class="pill mute">не начато</span>
<span class="pill warn">в работе</span>
<span class="pill info">закрыто</span>
```

После правки — пересборка.

## Сборка

Нужен скилл `anthropic-skills:analysis-to-html`.

```bash
python <skill>/scripts/build_report.py \
    docs/spec/content.html docs/spec/meta.json \
    -o docs/backend-target-spec.html
```

Скрипт печатает число разделов, диаграмм, размер и результат проверки автономности.
Жалоба на внешний ресурс — ошибка, а не предупреждение: документ перестал открываться
без интернета.

Перед сборкой полезно прогнать линтер — он ловит переносы `<br>` в подписях Mermaid
(рантайм инициализирует библиотеку с `securityLevel: strict`, разметка в подписях
вырезается) и слишком длинные `.fact`:

```bash
python <skill-gen-system-ontology>/scripts/lint_html.py docs/spec/content.html
```

## Проверка после сборки

Открыть файл в браузере и убедиться, что все шесть диаграмм отрисовались: пустая
`.diagram-card` без `svg` внутри означает синтаксическую ошибку Mermaid, которая при
сборке не ловится — библиотека парсит текст только в браузере.
